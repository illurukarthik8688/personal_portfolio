# Comments System Setup Instructions

## Overview
Your portfolio now has a custom comment system where visitors can leave comments without any authentication. You (as admin) can approve/delete comments via a password-protected admin panel.

## Setup Steps

### 1. Create a Supabase Project
1. Go to [https://supabase.com](https://supabase.com) and sign up/login
2. Click "New Project"
3. Choose your organization, enter project name, database password, and region
4. Wait for the project to be created (~2 minutes)

### 2. Create the Comments Table
1. In your Supabase dashboard, go to "SQL Editor"
2. Click "New Query"
3. Paste and run this SQL:

```sql
create table comments (
  id bigint generated by default as identity primary key,
  name text not null,
  message text not null,
  approved boolean default false,
  created_at timestamptz default now()
);

-- Enable Row Level Security
alter table comments enable row level security;

-- Policy: Anyone can read approved comments
create policy "Anyone can read approved comments"
  on comments for select
  using (approved = true);

-- Policy: Anyone can insert comments (they start as unapproved)
create policy "Anyone can insert comments"
  on comments for insert
  with check (true);

-- Policy: Service role can do anything (for admin operations)
-- This is automatically handled by the service_role key
```

4. Click "Run" to execute the SQL

### 3. Get Your Supabase Keys
1. In your Supabase dashboard, go to "Settings" → "API"
2. Copy the following:
   - **Project URL** (under "Project URL")
   - **anon public** key (under "Project API keys")

### 4. Create Environment Variables File
1. In your project root, create a file named `.env.local`
2. Add your Supabase credentials:

```env
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key-here
```

**Important:** Add `.env.local` to `.gitignore` to keep your keys private!

### 5. Update .gitignore
Make sure `.env.local` is in your `.gitignore` file:

```
.env.local
.env*.local
```

### 6. Change Admin Password
Open `src/components/Comments.tsx` and find this line:

```typescript
const ADMIN_PASSWORD = 'admin123'; // Change this to a secure password
```

Replace `'admin123'` with a strong password of your choice.

### 7. Test Locally
1. Run your dev server:
   ```bash
   npm run dev
   ```
2. Navigate to the Contact section
3. Try submitting a comment (it will be pending approval)
4. Click "Admin" button, enter your password
5. Approve or delete comments

### 8. Deploy to Netlify
When deploying to Netlify, you need to add your environment variables there:

1. In Netlify dashboard, go to your site → "Site settings" → "Environment variables"
2. Add:
   - `VITE_SUPABASE_URL` = your Supabase URL
   - `VITE_SUPABASE_ANON_KEY` = your Supabase anon key
3. Redeploy your site

## Features

### For Visitors
- Leave comments with just a name and message (no sign-up required)
- Comments are held for moderation before appearing publicly
- See all approved comments

### For You (Admin)
- Click "Admin" button on the comments section
- Enter your admin password
- See all comments (approved and pending)
- Approve/unapprove comments with one click
- Delete spam or inappropriate comments
- Green badge = approved, Yellow badge = pending approval

## Security Notes

1. **Admin Password:** The admin password is stored in the component code. For production, consider:
   - Using environment variable: `VITE_ADMIN_PASSWORD`
   - Implementing a proper backend authentication system
   - Using Supabase Auth for admin login

2. **Row Level Security (RLS):** The SQL setup includes RLS policies that:
   - Allow anyone to read approved comments
   - Allow anyone to insert comments (they start unapproved)
   - Admin operations use the anon key with client-side password check

3. **Rate Limiting:** Consider adding rate limiting in Supabase or a backend to prevent spam.

## Troubleshooting

### Comments not showing up?
- Check browser console for errors
- Verify `.env.local` exists and has correct keys
- Check Supabase dashboard → "Table Editor" → "comments" to see if data is there
- Verify RLS policies are enabled in Supabase

### Admin login not working?
- Check you updated the `ADMIN_PASSWORD` in `Comments.tsx`
- Clear browser cache and try again

### Deployment issues?
- Verify environment variables are set in Netlify
- Check Netlify build logs for errors
- Ensure `.env.local` is NOT committed to git
